# UI 易用性测试报告

## 1. 目的

本报告记录了对“离线可访问多模态本地内容检索系统”第 5 周 Flutter 用户界面所开展的易用性评估工作。

本次评估旨在检验普通用户能否在极少外部协助的情况下，直观理解并顺利完成系统的核心业务工作流。

主要评估维度包括：

- 导航结构的清晰度
- 文件库管理工作流
- 检索交互流程
- 检索结果的呈现与可理解性
- 设置项的可发现性
- 纯键盘无障碍操作体验
- 高对比度与动态文字缩放流程
- 屏幕阅读器可用性与朗读体验
- 错误提示与状态即时反馈

## 2. 评估范围

评估覆盖了以下核心界面：

1. 文件库（File Library）
2. 搜索界面（Search）
3. 设置界面（Settings）

本次评估聚焦于当前已实现的 Windows 原生桌面原型。后端大模型推理性能与向量检索准确率基准评测不包含在本 UI 易用性报告范畴内。

## 3. 评估方法

界面评估采用了**基于任务的形成性测试方法（Task-based formative testing）**。

评估人员在应用的正常运行状态下逐项尝试各核心任务。针对关键任务，额外使用纯键盘操作以及 NVDA 屏幕阅读器进行了重复测试。

评估考量维度：

- 任务是否能够顺利闭环完成
- 相关交互控件是否易于被用户发现
- 界面是否提供了清晰易懂的状态反馈
- 焦点位置与导航路径是否稳定可预期
- 在开启各类无障碍功能时工作流是否依然顺畅可用

鉴于当前为第 5 周阶段性原型，本次测试由开发者进行形成性评估，未组织大规模外部用户测试群体。

本次测试未记录正式的逐秒任务完成耗时，本报告严格依据实测事实撰写，不编造未采集的耗时或满意度分值。

- 设置

## 7. 文件库管理工作流

文件库页面为管理本地知识库内容提供了直观的起点。

界面清晰传达了以下信息：

- 当前是否已导入文件
- 索引构建是否正在进行中
- 索引构建是成功还是失败
- 本地库中已有可用文件的列表清单
- 哪些管理与维护操作可用

状态消息均以可视文本直接呈现，并配置了无障碍实时区域（Live-region），方便辅助技术同步朗读。

### 文件库工作流结论

**评估结论：通过 (Passed)**

当前工作流反馈充分满足第 5 周原型需求。对于耗时较长的批量文件索引，建议在未来版本中提供更细粒度的进度条与状态细节。

## 10. 无障碍工作流评估

### 10.1 纯键盘操作体验

实测验证了以下行为：

- 使用 `Tab` 键顺向流转焦点
- 使用 `Shift+Tab` 键逆向回退焦点
- 使用 `Enter` 或 `Space` 键激活按钮与开关
- 使用 `Alt+1`、`Alt+2`、`Alt+3` 快速切页
- 使用 `Ctrl+F` 直接定位搜索框
- 无需鼠标即可完成字号加减缩放
- 全流程未出现任何焦点死锁（Keyboard Trap）

**测试结论：通过 (Passed)**

### 10.2 NVDA 屏幕阅读器支持

在将原生的 Flutter Slider 替换为无障碍定制的字号调节组件后，NVDA 能够顺畅朗读所有页面内容及交互式控件。

最终方案整合了：

- 语义化滑块属性声明
- 实时百分比数值播报
- 增大与减小动作支持
- 可视化进度条指示
- 独立的键盘无障碍调节按钮

**测试结论：完成兼容性修复后通过 (Passed after compatibility fix)**

### 10.3 高对比度与大字号缩放

高对比度深色模式与文字动态缩放均通过了人工肉眼与自动化测试双重校验。

自动化测试证实，在测试窗口尺寸下，界面在 200% 字号放大极限状态下未产生任何 Flutter 布局溢出或渲染异常。

**测试结论：在测试的 Windows 环境下通过 (Passed)**

## 11. 已发现并解决的问题记录

| 缺陷编号 | 问题描述 | 用户影响 | 解决方案 | 状态 |
|---|---|---|---|---|
| UI-01 | 鼠标点击破坏当前焦点后全局快捷键失效 | 纯键盘用户可能临时失去切页快捷键响应 | 将快捷键监听提升至全局硬件按键事件分发层处理 | 已解决 (Resolved) |
| UI-02 | 搜索结果测试用例假定精确文件名匹配，与实际带序号的标题格式不一致 | 导致自动化 UI 测试误报失败，尽管界面显示正常 | 更新测试断言逻辑以匹配真实的结果展示格式 | 已解决 (Resolved) |
| UI-03 | 搜索标签存在重复的语义树匹配项 | 自动化语义匹配规则过于严苛导致测试报错 | 调整测试校验逻辑以兼容合法的语义节点结构 | 已解决 (Resolved) |
| UI-04 | 运行 NVDA 时原生 Flutter Slider 触发 Windows AXTree 树更新崩溃报错 | NVDA 仅能朗读静态文本，无法识别并操作交互控件 | 用“语义滑块信息 + 线性进度条 + 步进调节按钮”重构替换了原生 Slider | 已解决 (Resolved) |
| UI-05 | 语义测试在执行结束时遗留了未释放的句柄 | 导致无障碍测试清理流程抛出异常 | 在 `try...finally` 块中确保句柄百分之百安全释放 | 已解决 (Resolved) |

## 12. 正向优势总结

本次易用性评估总结出以下系统亮点：

- 三屏式基础架构清晰易懂，上手成本低。
- 一级导航项使用通俗规范的中文命名。
- 支持 `Ctrl+F` 秒级唤起搜索并聚焦。
- 检索结果同时列出文件名与完整本地物理路径。
- 状态提示覆盖空状态、加载中、成功及失败全生命周期。
- 无障碍偏好设置集中统一，便于集中管理。
- 字号缩放提供精确的可视化百分比读数。
- 完美兼顾鼠标点击与纯键盘快捷操作。
- 在 Windows 原型上完成了严谨的 NVDA 屏幕阅读器实测适配。
- 核心 UI 行为与无障碍逻辑拥有自动化 Widget 及 Semantics 测试兜底保障。

## 13. 遗留易用性风险与局限

当前仍存在以下局限性：

1. 本次形成性测试由开发者执行，尚未引入多元化的外部真实用户样本。
2. 尚未采集大样本量下的量化任务完成时间、错误率及 SUS 满意度量表评分。
3. 界面主要在 Windows 环境下验证，尚未覆盖 Flutter 支持的全平台。
4. 当本地知识库导入海量文档时，可能需要引入更高级的文件过滤、排序、分页与批量进度展示。
5. 检索结果的相关度与模型生成质量会影响用户的感知易用性，但该项属于算法范畴，未列入本 UI 评估。
6. 屏幕阅读器在不同 NVDA 版本及不同 Windows 补丁版本下的表现可能存在微小差异。

## 14. 针对后续版本的改进建议

1. 招募 3 至 5 名典型目标用户开展正规的可用性实测。
2. 邀请至少 1 名日常重度依赖屏幕阅读器的视障用户参与体验。
3. 规范记录任务完成耗时、所需干预协助次数、操作失误及满意度评分。
4. 在 NVDA 之外补充对 Windows 自带朗读人（Narrator）的兼容测试。
5. 若后续发布 Android 或 macOS 版本，补充对 TalkBack 和 VoiceOver 的专项测试。
6. 为海量文件场景增加文件列表过滤、搜索与批量删除功能。
7. 在 Flutter 框架升级后，持续对键盘焦点流转及 Windows 无障碍树（AXTree）开展回归测试。

本系统Flutter 用户界面完整支持了预定的原型业务工作流，在 Windows 测试环境下通过了鼠标、键盘以及 NVDA 屏幕阅读器的全面交互检验。

在完成无障碍兼容性与全局快捷键专项优化后，预设的 **11 项形成性测试任务全部顺利通过**。
